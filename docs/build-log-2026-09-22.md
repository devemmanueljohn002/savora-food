# Savora Food — Build Log (2026-09-22)

End-to-end implementation of all six frontends (Public, Customer, Vendor, Rider, Admin, Super Admin) plus the backend APIs they need, on the existing Next.js 16 + PostgreSQL codebase.

## Phase 0 — Schema & seed
- New migration `src/server/migrations/002_roles_dashboards.sql`: `SUPER_ADMIN` role, `admin_permissions`, `email_verification_tokens`, `product_variants` (+ `products.preparation_minutes`, unique `(product_id, name)`), `vendor_staff`, `vendors.commission_rate`, `vendor_payouts`, rider verification columns on `delivery_partners` (+ unique `user_id`), `rider_documents`, `orders.preferred_delivery_time`, `coupons.vendor_id`, `platform_settings` defaults, `categories.description`.
- `scripts/seed.ts`: super admin, approved demo rider + licence document, pending vendor (`Fresh Bites Kitchen`), product variants, coupons (`WELCOME10`, `SAVE1500`, `ROYAL5`), a paid payout, booked + pending catering requests with quote, customer notification. Made re-runnable (no duplicate rows).
- Demo logins (password `Demo_User_123!` unless noted): `customer@savorafoods.com`, `rider@savorafoods.com`, `vendor.*@demo.savora.test`, `admin@savora.food` + `superadmin@savora.food` (passwords in `.env.local` / seed fallbacks).

## Phase 1 — Auth & account
- Pages: `/login` (`next` redirect), `/register` (customer/vendor/rider; vendors go to onboarding), `/forgot-password`, `/reset-password?token=`, `/verify-email` (auto-verify + resend), `/vendor/onboarding` (VENDOR-only, status banner), `/auth` → redirects to `/login`.
- APIs: verification email on register (non-blocking), `POST /api/auth/verify-email`, `GET/PATCH /api/account`, `POST /api/account/password` (revokes sessions, forces re-login), `GET/PATCH /api/vendor/onboarding`.
- `proxy.ts`: `SIGN_IN` fixed to `/login`; added `SUPER_ADMIN`, `/vendor/onboarding` and `/rider` rules; `requireAdmin` covers ADMIN + SUPER_ADMIN, new `requireSuperAdmin`.

## Phase 2 — Customer
- APIs: `/api/favorites` (toggle/list), `/api/notifications` (list, mark read), `/api/catering/requests` + `[id]` (create with date/min-guest validation, accept → `BOOKED`, cancel), `/api/addresses/[id]`, review POST (delivered-order check) + `/api/orders/reviewable`.
- Pages: `/dashboard` hub with `?tab=` (overview/orders/catering/favorites/notifications), real `/account/profile` + `/account/addresses`; `/account/orders` and `/account/favorites` redirect to dashboard tabs.
- Wired the catering marketplace form to the API; review form on product pages.

## Phase 3 — Vendor
- `src/server/vendors.ts` (`getVendorContext` blocks unapproved kitchens, `notifyUser`, slug helpers); local uploads (`POST /api/uploads`, 5 MB images, gitignored).
- APIs: product CRUD (+ soft-delete with order history), variant CRUD, order list/detail/advance (`PAID→CONFIRMED→PREPARING→READY_FOR_PICKUP`)/cancel, catering list/quote/decline, earnings, analytics, profile (+bank/branding).
- Pages: dashboard, orders (+ detail), products (+ new/edit with variant manager), catering (+ detail), payouts, profile; shared `VendorNav`/`VendorShell`, `ProductForm`, `ImageUploader`.

## Phase 4 — Rider
- `src/server/riders.ts` (verification gate); APIs: profile/status toggle, document upload, job board, row-locked job accept (403 offline/unapproved, 409 taken), delivery detail + `pickup`/`in_transit`/`deliver`/`fail` (fail releases the order), earnings.
- Pages: dashboard (online toggle, jobs, current trip), deliveries (+ detail), earnings, profile with document verification.

## Phase 5 — Admin
- `src/server/admin.ts` (admin guard, audit log, pagination); APIs: overview, vendors/riders/customers/orders/products moderation, payout create/settle, coupon CRUD, category CRUD — all mutating actions audit-logged with user/vendor/rider notifications.
- Reusable `Table` component (`src/components/ui/table.tsx` + `.table` CSS); all 9 `/admin/*` pages.

## Phase 6 — Super Admin
- APIs: admin list/create-or-promote/update (self-change forbidden), platform settings GET/PATCH (validated keys), audit log, platform analytics (GMV, top vendors/categories, growth, catering funnel).
- All 5 `/super-admin/*` pages; ADMIN gets 403 on super-admin routes but full admin access.

## Phase 7 — Checkout coupons
- Migration `003_coupon_code.sql` (`orders.coupon_code`); pure `computeCouponDiscount` (+5 unit tests); platform-wide coupons apply per vendor order, vendor-scoped to one kitchen; atomic `used_count` claim; `POST /api/orders/checkout/quote` preview; coupon UI in checkout with live savings.

## Verification
- `npm run typecheck`, `npm run lint` (0 errors), `npm run test` (28/28), `npm run build` green after every phase.
- Every flow smoke-tested live against the dev server (register → verify → ordering → vendor → rider → admin → super-admin → coupons); test data reverted afterward.
- Known environment quirks: transient Neon DNS/500 flakes (retry succeeds); `postgres.js` needs `sql\`col\`` fragments or fetch-merge instead of bare column names in `UPDATE`.
